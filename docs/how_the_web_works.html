How the Web Works

When you type an address into your browser and press enter, a surprising number of steps happen in a fraction of a second. This page walks through the main ones, from the domain name to the page appearing on your screen.

DNS: finding the server

Computers locate each other using numeric IP addresses, but people prefer names such as example.com. The Domain Name System, or DNS, is the global directory that translates a name into an IP address. Your browser first checks its own cache, then asks a DNS resolver, which may query several other servers before returning an answer.

HTTP: asking for the page

Once the browser knows the server's address, it opens a connection and sends an HTTP request. The request contains a method, usually GET to fetch a page or POST to submit a form, plus headers describing the browser and the content it accepts.

The server replies with a status code and the content. Some codes worth remembering:

  • 200 means the request succeeded.
  • 301 means the page has moved permanently to a new address.
  • 404 means the server could not find the requested page.
  • 500 means something went wrong on the server itself.

HTTPS and encryption

Plain HTTP sends everything as readable text, so anyone on the network could read or change it. HTTPS wraps HTTP inside TLS encryption. During a short handshake the browser verifies the server's certificate and both sides agree on keys, after which all traffic is encrypted. The padlock icon in the address bar indicates that this succeeded.

Rendering the page

The browser receives HTML and builds a tree called the DOM. It then downloads linked stylesheets, scripts and images, applies the CSS rules to work out layout and appearance, and paints the result on screen. JavaScript can change the DOM afterwards, which is how pages update without reloading.
